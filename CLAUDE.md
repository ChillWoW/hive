# hive

Repo: https://github.com/ChillWoW/hive (private) — licensed under GPL-3.0.

## What it is

A desktop UI for driving coding-agent CLIs (Claude Code, Codex, OpenCode, …) from one place.

- No provider APIs: Hive spawns the CLIs the user already has installed (e.g. `claude` with stream-json input/output, `codex app-server`) and talks to them over stdin/stdout.
- Each CLI's output is normalized into one common event stream: text, reasoning, tool calls/results, questions, done.
- The UI renders that stream as a live transcript.

## Stack

Desktop app "Hive": Tauri 2 shell (Rust, `src-tauri/`) around a React 19 + Vite + Tailwind v4 frontend (`src/`). Package manager is bun.

## Commands

- `bun run dev` — frontend only, Vite on http://localhost:1421
- `bun run dev:local` — Tauri dev with the dev config (`Hive Dev`, blue icon)
- `bun run dev:prod` — Tauri dev with the prod config
- `bun run build` — `tsc -b && vite build` into `build/`
- `bun run lint` — oxlint
- `bun run proto` — regenerates `src/proto/` (TS types) from `crates/proto`. Also runs on any `cargo test -p hive-proto`.
- `cargo run -p hive-harness --bin hive-run -- [--mock|--codex|--opencode] [--access mode] [--plan] [--model haiku] "<prompt>"` — drive a harness from the terminal and print its events (`--json` for raw `AgentEvent`s). Answers questions and follow-ups on stdin; Ctrl+C interrupts.
- `cargo test -p hive-harness --test claude_live -- --ignored --test-threads 1` — live tests against the real `claude` CLI on Haiku (spends tokens).
- `cargo test -p hive-harness --test codex_live -- --ignored` / `cargo test -p hive-engine --test codex_live -- --ignored` — live tests against the real `codex` CLI on the account's default model (spends tokens).
- `cargo test -p hive-harness --test opencode_live -- --ignored --test-threads 1` — live tests against the real `opencode` (2.x) on its default model (spends tokens).
- `cargo run -p hive-usage --release --example report -- 30` — the Usage panel's report for this machine's last N days, printed (scan cache in a temp dir; `--data <dir>` to use another).
- `cargo test -p hive-mcp --test live -- --ignored --test-threads 1` — Claude (Haiku), Codex and OpenCode each calling a Hive MCP tool through the engine in supervised mode, and (`_waits_` tests) waiting 75s on one, past the CLIs' own timeouts (spends tokens).
- `bun run icons` — regenerates `src-tauri/icons/{prod,dev}` and `public/favicon.svg` from `src-tauri/icons/icon.svg` / `icon.dev.svg`. Use this, not `tauri icon` directly (it pads the macOS `.icns`).
- `bun run release <version>` — bumps the version (package.json, `tauri.conf.json`, `src-tauri/Cargo.toml`, Cargo.lock), commits `chore: release v<version>` and tags it; refuses a dirty tree. `git push --follow-tags` then runs `.github/workflows/release.yml` (`tauri-action`): Windows, the NSIS installer; then macOS, one universal (`universal-apple-darwin`) `.dmg` + updater `.app.tar.gz`, ad-hoc signed (`signingIdentity: "-"` in `tauri.macos.conf.json`), not notarized. Both signed for the updater (`TAURI_SIGNING_PRIVATE_KEY`/`_PASSWORD` secrets), merged into one `latest.json` on the GitHub release. A local `tauri build` needs those env vars too (`createUpdaterArtifacts`).

## Layout

- `src/main.tsx` — entry; renders `src/App.tsx` (shell: `src/layout/` sidebar + top bar, an overlay layer below the top bar that portalled overlays mount into, a chrome layer over the top bar where a modal's second backdrop dims it, a drag region under the dim stopping short of the window controls (`WINDOW_CONTROLS_WIDTH`), the settings modal).
- `src/stores/useLayoutStore.ts` — columns: sidebar (300), conversation, right sidebar, file panel at the edge (`RightPanels`, each a `SidePanel` resized by its left edge; toggles in the top bar's right corner). Limits: files 220–440 (286 default), right ≥360 (520 default), conversation ≥300 (panels shrink to their minimums before it goes under 560). `panelLayout`: when the minimums don't fit the window, the column opened longest ago hides (still open; toggling it brings it back as the newest). `rightMaximized` (the button at the tab strip's end): the right sidebar takes the conversation's room too (conversation inert, no resize edge, title hidden); the left sidebar and file panel stay; closing the right sidebar restores it. Panel open state, widths and `rightMaximized` persisted as `hive.layout`. The right sidebar is `src/rightbar/`.
- `src/ui/` — Base UI–based primitives (Button, Menu, Modal (`onClose`; `useLastNonNull` keeps a dialog's subject while it animates out), Popover, Tooltip, …) plus `IconButton` (the square icon button with its label as tooltip; `iconButtonClassName`), `ConfirmDialog` (title, body, error, Cancel + destructive button, busy state; every delete/undo confirm), `RowMenu` (a card row's "⋯" menu), `ComboboxCard` (the pickers' combobox popup + search), `ChipPopover` (a composer chip opening a card: context, usage, background tasks), `chip.ts` (chip, picker and card classes), `useInlineRename` (rename in place: sidebar rows, file tree), and `DotMatrixSpinner` (3×3 dots in random patterns for open-ended work; `pattern` holds one, e.g. `DOT_MATRIX_FULL` for waiting) and `MorphHeight` (animates its height when its content is swapped, by `swapKey`; instant otherwise) and `HiveMark` (the logo's hexagon and dot, no tile, in `currentColor`) and `FileIcon` (a file or folder's material-icon-theme icon, as VS Code resolves it: `src/lib/fileIcons.ts`; the SVGs are separate assets, never inlined — `assetsInlineLimit` in `vite.config.ts`), exported from `ui/index.ts`. Use `FileIcon` wherever a file is shown (attachment chips, tool file badges, `@` mentions).
- `src/settings/` — settings UI and state. `store.ts`: zustand store (document, modal open/page), writes queued in order and optimistic; `useSetting(section, key)` gives a row its value, setter, `modified` and `reset`. `api.ts`: Tauri commands, localStorage fallback under plain `bun run dev`. `useSettingsRuntime` (mounted in `App`): loads, toggles the modal on the `openSettings` shortcut, re-reads the file on window focus. Settings › Chats › Text generation (`pages/TextGenerationRow.tsx`): the `textGeneration` model, a `ModelPicker` (null `config` = "Automatic", no fast mode); reset goes back to automatic. Add a setting only once something reads it (field in `crates/proto/src/settings.rs`, row on a page in `pages/`). Pages live in `pages/` and are registered in `pages/index.tsx`; rows use `SettingsSection`/`SettingRow`, which self-filter for search. `KeyboardPage`: a recorder per action (Escape cancels, Backspace unbinds, taking another action's combo unbinds that one), "Send with" (Enter / Mod+Enter). `WorktreesPage`: `worktrees.location` (text field saved on blur/Enter, Escape reverts; placeholder from `worktrees_default_dir`; folder picker) `worktrees.branchNaming` (a menu styled as the diff tab's scope menu: Static prefix / Semantic prefix) and, for static, `worktrees.branchPrefix` (default `hive`, empty for none), `worktrees.deleteBranch` (off by default: deleting a worktree chat deletes its branch too, once the worktree is gone), handed to the engine live by `settings::apply` (`src-tauri/src/settings.rs`: `~` expanded, a relative path means the default).
- `src/keybindings/` — custom shortcut layer. Bindings live in settings (`keyboard` section, `KeyboardSettings`: strings like `Mod+Shift+P`, `Mod` = Cmd on macOS / Ctrl elsewhere, empty = unbound). `actions.ts`: the actions (id = settings key, label, `category` (a section on the Keyboard page, from `CATEGORIES`), `scope` global or composer, `repeats`); a new one needs a field in `KeyboardSettings` and a row here. `shortcut.ts`: parse / canonical form / from a `KeyboardEvent` (letters by `key`, punctuation by `code`) / platform display / `checkAssignable` (characters need Mod/Ctrl/Alt; editing combos reserved). `runtime.ts`: `useKeybindingsRuntime` (mounted in `App`) is the one `window` keydown listener (bubble phase, skips `defaultPrevented`; with settings open only `openSettings` runs); components handle actions with `useShortcut(id, handler)` (latest mounted wins; return false to pass the key on); `COMPOSER_SCOPE` marks the composer for composer-scoped actions. `useBinding(ref)`: an action's current binding, or a fixed combo (`Escape`) as is. Show shortcuts with `<Tooltip.Content shortcut="newChat">` (action id or fixed combo; muted text on the right, nothing while unbound) or `ShortcutKeys` (`plain` text like the sidebar Settings button, or `caps`); no native `title=` tooltips. Handlers: TopBar (new chat, new terminal, diff, history, sidebar, file panel, right sidebar, search files (`openFileSearch` in `src/files`: shows the panel, focuses its search), close tab (`closeShownTab`: the right sidebar's shown tab, passes the key on while it's hidden or empty), back/forward; also the mouse side buttons), `Composer` (focus; `sendInBackground` (Mod+Shift+Enter) matched in the field's own keydown, since CodeMirror takes Enter combos first: in the new-chat view the chat starts without being opened (`send`'s `background`; its outbox entry stays out of the new-chat view unless it fails), elsewhere a plain send), `ChatView` (plan mode), `Transcript` (find in chat), `ChatList` (previous/next chat in sidebar order; archive chat (Mod+Shift+A): the open one, then the one below it, else above, else the new-chat view; an archived one is unarchived), `useSettingsRuntime` (settings), `useUsageRuntime` (usage).
- `src/chats/` — chat data layer. Helpers: `workDir`, `chatTitle` (title, else folder name), `isBusy(status)` (working or awaiting input), `activity`, `isUnseen`. `api.ts`: engine commands, watches over `Channel`s (no backend under plain `bun run dev`: empty snapshots, writes reject). `store.ts`: zustand + immer store; `useChatsRuntime` (mounted in `App`) watches the chat list and sessions; `useChatMessages(chatId)` holds that chat's message watch while mounted (ref-counted `retainMessages`) and folds events with `foldEvent`. `send(target, prompt)` mints the user message id, shows the prompt from the outbox at once, creates the chat first for a `{ cwd, config }` target (and selects it), then queues a `send` command; the entry leaves the outbox when the saved message with that id arrives, or keeps the rejection as an error (`discard` drops it). `activeChatId` null is the new-chat view; `select` keeps browser-style `back`/`forward` stacks of `Place`s (chat + open subagent path; `goBack`/`goForward`, deleted chats pruned).
  `send(target, prompt, attachments?)`: attachments ride the command and the outbox entry. Also `updateConfig` (optimistic, reverted if refused), `interrupt`, `answer`, and for queued prompts `cancelQueued`, `reorderQueued`, `sendNow` (optimistic; the outbox follows the engine's `queue` updates).
- `src/chat/handoff.ts` — "Continue in <agent>" (after t3code's context handoff, but into a new chat): `continueIn(chat, config)` calls `chats.handoff` (`handoff_chat`; opens the new chat), moves the old chat's draft (text, files, diff comments: `moveDraft`) over, else fills in "Continue where the previous agent left off."; `handoffConfig` (the chat's settings fitted to another harness), `handoffBlocked` (busy, or no prompt yet). Entry points: the model picker (`ModelPicker`'s `handoff`: a started chat lists every enabled harness's models, another's continues the chat there, as t3code's picker switches providers), the sidebar row menu, the palette. The new chat's transcript opens with `HandoffCard` (`src/transcript/HandoffCard.tsx`: a divider drawn as a compaction's, as t3code shows a provider switch: "Context handoff pending" shimmering while the summary is written, then "Context handoff", old harness + model → new; a click opens the old chat); its Send waits while the summary is written (`Composer`'s `hold`); the old chat ends with `ContinuedRows` (the same divider, "Continued in" + the new chat's model, opening it).
- `src/chat/ChatView.tsx` — the main pane: transcript + composer for the active chat; while a subagent is open (the chats store's `subagent`: spawn-id path in the active chat, nested ones deeper; `openSubagent` / `openParent` are places in Back/Forward history; the top bar shows `title / subagent / …`) `SubagentView` instead: its task as the prompt, its `thread` as the reply (live), and a bar in the composer's place (avatar, task, agent type · model, state · elapsed, "Runs on its own", Open parent). A spawn still listed in `Session::background` (by `toolCallId`, the `LiveTasks` context) counts as running past its turn ; elapsed comes from the spawn's `startedAt`/`endedAt`, else the task's `startedAt`, else what this window saw (spawns saved before the stamps). Claude's "Async agent launched…" call result is never shown as a result (`spawnResult`); for the new-chat view a centred composer until the first prompt. While the live turn waits on an `input` part, `QuestionWizard` replaces the composer, the box growing into it and back (`MorphHeight`). Else a secret the agent asked for (`Session::secrets`, oldest first) shows `SecretRequestCard` there (label, reason as markdown, a masked field with show/hide, Save securely, Decline): the value goes to `answer_secret_request`, never into the chat. Queued prompts (outbox `queued`) sit in `QueuedTray` above the composer, not in the transcript: drag the handle (or arrow keys) to reorder; per row Edit (withdraws it into the draft), Send now, Remove; "paused after stop" with Resume when the queue is held. `ContextRing` sits right of the folder chip: `Chat::context` as a ring + percent (warning ≥75%, danger ≥90%, hidden until a window is reported), token counts in its tooltip; when the harness has `/compact` (a started chat) it opens a card instead with the counts and Compact context (sends `/compact`; disabled, with why, before a reply or while a turn runs). The trays above the composer (usage, goal, queued) share one card split by hairlines (`tray.ts`). `UsageRing` before it: the harness's plan usage (`useProviderUsage`), the most-used window as a blue ring (warning ≥80%, danger ≥95%; hidden when the harness reports none); click opens the account (email, plan) with a meter per window and its reset time. Both draw `Ring`. `BackgroundTasks` before them: the session's `background` (agents, shells, monitors left running between turns) as a blue chip ("2 shells"); click lists them grouped by kind, each with a round avatar (harness mark for agents, a dot matrix on its corner), running time and Stop; an agent shows its latest line and tool count and opens its `SubagentView`; a shell or monitor is a `ShellTaskRow`, laid out as an agent's: a round avatar with its kind's glyph and the dot matrix on its corner (a red dot once `failureOf` says its latest run failed), its description (else its command) with its port chip (`servedUrl`, opens in the browser) or failure chip, under it the newest line of its output, live (`useTaskOutput`, every 2s while listed); it doesn't open (the transcript's `ShellRow` has the output); ↑↓ / Enter / Backspace from the keyboard.
