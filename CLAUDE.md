# hive

Repo: https://github.com/ChillWoW/hive (private) — licensed under GPL-3.0.

## What it is

A desktop UI for driving coding-agent CLIs (Claude Code, Codex, OpenCode, …) from one place.

- No provider APIs: Hive spawns the CLIs the user already has installed (e.g. `claude` with stream-json input/output, `codex app-server`) and talks to them over stdin/stdout.
- Each CLI's output is normalized into one common event stream: text, reasoning, tool calls/results, questions, done.
- The UI renders that stream as a live transcript.

## Stack

Desktop app "Hive": Tauri 2 shell (Rust, `src-tauri/`) around a React 19 + Vite + Tailwind v4 frontend (`src/`). Package manager is bun.

## Commands

- `bun run dev` — frontend only, Vite on http://localhost:1421
- `bun run dev:local` — Tauri dev with the dev config (`Hive Dev`, blue icon)
- `bun run dev:prod` — Tauri dev with the prod config
- `bun run build` — `tsc -b && vite build` into `build/`
- `bun run lint` — oxlint
- `bun run proto` — regenerates `src/proto/` (TS types) from `crates/proto`. Also runs on any `cargo test -p hive-proto`.
- `cargo run -p hive-harness --bin hive-run -- [--mock] [--model haiku] "<prompt>"` — drive a harness from the terminal and print its events (`--json` for raw `AgentEvent`s). Answers questions and follow-ups on stdin; Ctrl+C interrupts.
- `cargo test -p hive-harness --test claude_live -- --ignored --test-threads 1` — live tests against the real `claude` CLI on Haiku (spends tokens).
- `bun run icons` — regenerates `src-tauri/icons/{prod,dev}` and `public/favicon.svg` from `src-tauri/icons/icon.svg` / `icon.dev.svg`. Use this, not `tauri icon` directly (it pads the macOS `.icns`).

## Layout

- `src/main.tsx` — entry; renders `src/App.tsx` (shell: `src/layout/` sidebar + top bar, an overlay layer below the top bar that portalled overlays mount into, the settings modal).
- `src/ui/` — Base UI–based primitives (Button, Menu, Modal, Select, …) plus `DotMatrixSpinner` (3×3 dots in random patterns for open-ended work; `pattern` holds one, e.g. `DOT_MATRIX_FULL` for waiting) and `MorphHeight` (animates its height when its content is swapped, by `swapKey`; instant otherwise), exported from `ui/index.ts`.
- `src/settings/` — settings UI and state. `store.ts`: zustand store (document, modal open/page), writes queued in order and optimistic; `useSetting(section, key)` gives a row its value, setter, `modified` and `reset`. `api.ts`: Tauri commands, localStorage fallback under plain `bun run dev`. `useSettingsRuntime` (mounted in `App`): loads, toggles the modal on the `openSettings` shortcut, re-reads the file on window focus. Add a setting only once something reads it (field in `crates/proto/src/settings.rs`, row on a page in `pages/`). Pages live in `pages/` and are registered in `pages/index.tsx`; rows use `SettingsSection`/`SettingRow`, which self-filter for search. `KeyboardPage`: a recorder per action (Escape cancels, Backspace unbinds, taking another action's combo unbinds that one), "Send with" (Enter / Mod+Enter).
- `src/keybindings/` — custom shortcut layer. Bindings live in settings (`keyboard` section, `KeyboardSettings`: strings like `Mod+Shift+P`, `Mod` = Cmd on macOS / Ctrl elsewhere, empty = unbound). `actions.ts`: the actions (id = settings key, label, `scope` global or composer, `repeats`); a new one needs a field in `KeyboardSettings` and a row here. `shortcut.ts`: parse / canonical form / from a `KeyboardEvent` (letters by `key`, punctuation by `code`) / platform display / `checkAssignable` (characters need Mod/Ctrl/Alt; editing combos reserved). `runtime.ts`: `useKeybindingsRuntime` (mounted in `App`) is the one `window` keydown listener (bubble phase, skips `defaultPrevented`; with settings open only `openSettings` runs); components handle actions with `useShortcut(id, handler)` (latest mounted wins; return false to pass the key on); `COMPOSER_SCOPE` marks the composer for composer-scoped actions. `useBinding(ref)`: an action's current binding, or a fixed combo (`Escape`) as is. Show shortcuts with `<Tooltip.Content shortcut="newChat">` (action id or fixed combo; muted text on the right, nothing while unbound) or `ShortcutKeys` (`plain` text like the sidebar Settings button, or `caps`); no native `title=` tooltips. Handlers: TopBar (new chat, sidebar, back/forward; also the mouse side buttons), `Composer` (focus), `ChatView` (plan mode), `ChatList` (previous/next chat in sidebar order), `useSettingsRuntime` (settings).
- `src/chats/` — chat data layer. `api.ts`: engine commands, watches over `Channel`s (no backend under plain `bun run dev`: empty snapshots, writes reject). `store.ts`: zustand + immer store; `useChatsRuntime` (mounted in `App`) watches the chat list and sessions; `useChatMessages(chatId)` holds that chat's message watch while mounted (ref-counted `retainMessages`) and folds events with `foldEvent`. `send(target, prompt)` mints the user message id, shows the prompt from the outbox at once, creates the chat first for a `{ cwd, config }` target (and selects it), then queues a `send` command; the entry leaves the outbox when the saved message with that id arrives, or keeps the rejection as an error (`discard` drops it). `activeChatId` null is the new-chat view; `select` keeps browser-style `back`/`forward` stacks (`goBack`/`goForward`, deleted chats pruned).
  Also `updateConfig` (optimistic, reverted if refused), `interrupt`, `answer`, and for queued prompts `cancelQueued`, `reorderQueued`, `sendNow` (optimistic; the outbox follows the engine's `queue` updates).
- `src/chat/ChatView.tsx` — the main pane: transcript + composer for the active chat; for the new-chat view a centred composer until the first prompt. While the live turn waits on an `input` part, `QuestionWizard` replaces the composer, the box growing into it and back (`MorphHeight`). Queued prompts (outbox `queued`) sit in `QueuedTray` above the composer, not in the transcript: drag the handle (or arrow keys) to reorder; per row Edit (withdraws it into the draft), Send now, Remove; "paused after stop" with Resume when the queue is held. `ContextRing` sits right of the folder chip: `Chat::context` as a ring + percent (warning ≥75%, danger ≥90%, hidden until a window is reported), token counts in its tooltip — as in zeron.
- `src/sidebar/` — `ChatList` (in `layout/Sidebar`): Pinned (pin order), then each project (`useProjects` order, then folders only chats remember; first 6 chats, the open one always; "+" starts a new chat there), then Archived (folded). `ChatRow`: status dot (working / waiting / errored from the session, green when `isUnseen`), title, time ago (`time.ts`, one minute clock), harness mark; "⋯" and right-click open Rename (in place), Pin, Archive, Delete (confirm dialog). Fold state persisted as `hive.sidebar`. `useChatsRuntime` marks the open chat seen while the window has focus.
- `src/projects/` — `store.ts`: the projects picked on this device (zustand, persisted to localStorage as `hive.projects`; `add` appends one, a listed one stays put; `remove` deletes one and remembers it in `removed`, so its chats don't bring it back until it's added again). `useProjects` lists them merged with every chat's folder in a fixed order (first seen first), so projects never move. The folder picker reads it, adds each pick, and has a "⋯" menu per row (Delete).
- `src/notifications/` — `useNotificationsRuntime` (mounted in `App`), driven by the chat list watch: a session going `working` → idle/errored/closed, or to `awaitingInput`, sends a system notification (`@tauri-apps/plugin-notification`) while the window isn't focused; `awaitingInput` and a finished turn also play a chime (`playChime` in `sound.ts`: WebAudio, rising for input, falling for finished; unlocked on the first key/click). `badge.ts`: unseen non-archived chats as the dock/taskbar badge (Windows: a drawn overlay icon). Each behind a `notifications.*` setting (Notifications page).
- `src/harnesses/` — harness catalogs (`list_harnesses`; a static fallback under `bun run dev`), fetched at launch and when a picker opens. `useHarnesses`: every visible one (Settings › Providers); `useCatalogs`: those turned on in the `providers` settings section (`isEnabled`, keyed by `providerKey`: `claude-code` → `claudeCode`), what pickers offer. `fitConfig` makes a `ChatConfig` valid for a catalog; `slashCommands` prefers the live `Session::commands`. Mock is only shown in dev builds.
- `src/providers/` — Settings › Providers data: `api.ts` (`provider_*` commands; made-up statuses under `bun run dev`; `latestRelease` reads the CLI's npm dist-tag for its channel from the webview), `store.ts` (`refreshProvider` probes a CLI and checks its newest release at most every 10 min; `providers.install/update/signOut` run one action at a time per harness, then `afterChange` re-probes and refreshes catalogs). The page is `src/settings/pages/ProvidersPage.tsx` (a row per harness: version, login, Install / Update / Sign in, switch; opens into account, version, location) with `SignInDialog.tsx`.
- `src/composer/` — `Composer` (field beside the controls while it fits one line, else a two-row box, morphing between them as in Desktop/agent; one Send/Queue/Steer/Stop button; `/` command menu), `ModelPicker` (chip: harness mark, model, effort; card: provider tabs, search, starred models first, a Reasoning footer that opens the picked model's levels in a card beside it, as in Desktop/agent), `QuestionWizard`, `AccessPicker` before the model picker (access mode + plan-mode switch, as in zeron), `FolderPicker` under the box (projects from `useProjects` with `ProjectIcon`: the folder's favicon via `folder_icon`, else a tinted monogram, as in zeron). New chats get `workspace-write`; the access mode is remembered, plan mode isn't. `store.ts`: drafts per chat; the new chat's folder + config and starred models persisted to localStorage.
- `src/git/` — branches of a chat's folder. `store.ts`: each folder's `GitRepo` (null outside a checkout) shared by readers; `useGitRepo(cwd)` re-reads when stale (5s), on window focus and when an agent's turn in that folder ends; `useFolderBusy(cwd)` (an agent mid-turn there, by `workDir`; branch changes are disabled); `git.switchBranch/createBranch/deleteBranch` re-read afterwards. `api.ts`: `git_*` commands; an in-memory fake repo under `bun run dev`. `BranchPicker` (beside the `FolderPicker` chip, hidden outside a checkout): local branches by last commit, pick to switch, type a new name to create it off the current one (Enter or the footer); per row "⋯": New branch from here (`NewBranchDialog`, creates and switches), Copy name, Delete (not the checked-out one; `DeleteBranchDialog` warns when unmerged); a branch checked out in another worktree is marked "worktree" and can't be switched to or deleted. With `onBaseChange` it picks a new worktree's base instead (nothing checked out). `WorkspacePicker` (after the branch chip, new-chat view; hidden outside a checkout): Current checkout / Worktree, kept in the composer store's `newChat.workspace` (remembered; `newChat.base` isn't). `WorkspaceChip`: a started chat's, locked; a worktree's opens its branch, base and folder with Copy path / Copy branch name / Reveal. `ChatCard` shows the branch where the chat works ("· worktree"); `DeleteChatDialog` says the worktree goes, its branch stays, and warns about uncommitted changes in it. Worktree chats keep `cwd` as their project (sidebar, folder chip); `workDir(chat)` (`src/chats`) is where the agent runs, used by the branch chip and transcript paths.
- `src/transcript/` — `Transcript` (pins to the bottom while streaming, jump-to-bottom button), `UserMessage`, `AssistantMessage` (consecutive tool calls and thoughts → one `ToolGroup`: a muted "Thought process · Ran 3 commands · edited 2 files · 1 failed" header over a tree rail, one expandable line per item, open only while it's the tail of a running turn; subagent spawns as their own cards; text, questions and errors split groups — modelled on zeron's transcript), `Markdown` (Streamdown + Shiki via `@streamdown/code`; links open with the opener plugin), `diff.ts` (line diff for edits).
- `src/lib/cn.ts` — `cn()` (clsx + tailwind-merge) and `mergeClassName()`.
- `src/index.css` — Tailwind theme: `dark-*` / `primary-*` scales and `danger`/`success`/`warning`/`info` tokens.
- Cargo workspace at the root (`target/` there): `src-tauri/`, `crates/proto/`, `crates/harness/`, `crates/store/`, `crates/engine/`, `crates/git/`.
- `crates/proto/` (`hive-proto`) — wire types: `RunRequest`, `AgentEvent`, `ToolCall`, `MessagePart`/`Message`, `Chat`/`Session`, `Command` (the command ledger), `MessagesUpdate`/`ChatsUpdate` (what the engine's watchers stream). `ProviderStatus`/`ProviderAccount`/`SignInMethod` (`provider.rs`). `GitRepo`/`GitBranch` (`git.rs`). `Chat::worktree` (`Worktree`: root, path, branch, base) with `Chat::work_dir()`; `NewWorktree` (base, hint) for `create_chat`. `fold_event` folds events into message parts. `Settings` (`settings.rs`): sections of plain leaves (`chats.resumeInterrupted`, read by the engine at launch); `Settings::sanitize` applies JSON leaf by leaf, keeping only leaves that still deserialize, then clamps. `bun run proto` also writes `src/proto/defaults.ts` (`DEFAULT_SETTINGS`) from `Settings::default()`. Source of truth; `src/proto/` is generated by ts-rs, never hand-edited.
- `src/transcript/fold.ts` — `foldEvent`: AgentEvent → MessagePart, in place on an immer draft. Mirrors the Rust `fold_event`; change both together.
- `crates/harness/` (`hive-harness`) — `Harness::catalog()` → `HarnessCatalog` (models with reasoning levels, built-in slash commands, `access_modes`, capabilities: `steering`, `interrupt`, `attachments`, `plan`; `installed` checked per call). `Harness::run(RunRequest)` → `Run { events, handle }`; `RunHandle` sends follow-ups, answers `InputRequested`, interrupts, closes. `mock.rs` is a scripted turn that honors the same handle. `claude/`: `wire.rs` (stream-json frames), `normalize.rs` (frames → `AgentEvent`), `mod.rs` (process + control channel: `initialize`, `can_use_tool`, `interrupt`). As in zeron, `RunRequest::access` (`AccessMode`: supervised / auto-accept edits / full access) decides which `can_use_tool` calls become yes/no approval questions (`approval.rs`); `AskUserQuestion` always does. `plan` launches in `--permission-mode plan` and re-enters it each turn; approving `ExitPlanMode` drops to the access mode. `auto_approve` adds the skip-permissions flags. The sandbox level doesn't reach Claude. `run_title` (Claude, Mock; `supports_titles`): a one-turn run with `TITLE_INSTRUCTIONS` as system prompt, no tools, MCP servers or settings, no initialize. `provider.rs`: per-harness CLI management for Settings › Providers (`status`, `install`, `update`, `sign_out`, `SignIn::start` → `finish(code)`); Claude's is `claude/provider.rs` (`claude --version`, `claude auth status --json`, the official install script, `claude update`, `claude auth login` which prints a URL and reads the browser's code on stdin). `find_claude` falls back to the installers' default locations when `claude` isn't on PATH.
- `crates/git/` (`hive-git`) — a folder's branches over the installed `git` CLI: `repo` (branch or detached commit, local branches with upstream, ahead/behind, last commit, `merged` into HEAD; `None` outside a checkout), `switch` (`git switch`), `create` (validated with `check-ref-format`, `git switch -c` off a branch or commit), `delete` (`git branch -D`, never the checked-out branch). `repo` also gives the checkout's `root`, uncommitted `changes` (`status` without optional locks) and each branch's other `worktree`. Worktrees: `add_worktree` (branch `hive/<slug of the first prompt>`, numbered when taken, off the base or HEAD, at `<dir>/<repo name>`; the agent runs in the same subfolder `cwd` is of its repo), `restore_worktree` (blocking; re-adds a deleted worktree from its branch, or remakes the branch off `base`), `remove_worktree` (`git worktree remove --force`, else deletes the folder; retries while files are locked; prune; the branch stays). Tests use temp repos.
- `crates/store/` (`hive-store`) — durable state under one data dir: `hive.db` (SQLite, migrations in `MIGRATIONS`; chats, messages, commands as proto JSON plus query columns) and `journals/{chatId}.jsonl` (every event, tagged with its assistant message id). `start_turn` + `record` journal, fold and save a turn; `recover()` at boot expires pending commands and rebuilds streaming messages from their journals. `SettingsFile`: `settings.json` in the same dir (atomic writes; unreadable file moved to `settings.json.bak`).
- `crates/engine/` (`hive-engine`) — `Engine` runs chats over the store and harnesses. One live `Run` per chat, started on the first `Send` (resuming `harness_session_id`) and closed after `idle_timeout`. `queue_command` issues to the ledger, executes, settles; a `Send` mid-turn waits in the chat's queue (held by the engine, not the CLI) and stays `pending` until its own turn starts when the previous turn's `Done` arrives; a turn the user stopped holds the queue until the next one ends. `cancel_queued` (→ `Cancelled`), `reorder_queue` (publishes `MessagesUpdate::Queue`), `send_queued_now` (starts it now if idle, else moves it to the front and interrupts the running turn). Every event goes through `store.record` and out to watchers under the chat's lock, so `watch_messages` (snapshot, then `MessagesUpdate`s) never overlaps or misses. `watch_chats` streams `ChatsUpdate`s (chats + live `Session`s, which carry the run's `AvailableCommands`). `catalogs()` lists harnesses in registration order. `rename_chat`, `set_pinned` (unarchives), `set_archived` (unpins; a new turn unarchives), `mark_seen` and `delete_chat` (closes the run; `ChatsUpdate::Removed`) edit the chat under its lock. `ContextUsage` events are saved on the chat (`Chat::context`, so it outlives the run); a model change drops the stale window. `update_config` saves a chat's `ChatConfig` and closes its run (now if idle, else after the turn) so the next prompt starts one with the new config, resuming the session. `start()` runs `recover()` and, with `resume_interrupted` (the `chats.resumeInterrupted` setting), resends cut-short turns as `RESUME_PROMPT`. `titles.rs`: after a completed turn, an untitled chat is named in the background by a title run (the chat's harness if it supports titles; cheapest catalog model, minimal effort; empty temp dir; 30s timeout, 2 retries) from its first prompt; cleaned to one line, 60 chars; fallback is the prompt's first 7 words (48 chars), also used without a title run when `chats.autoTitle` is off (`set_auto_title`, pushed live from `src-tauri/src/settings.rs`). `Store::title_chat` only sets a missing title, so a rename wins. `create_chat_in_worktree` makes the worktree under `EngineConfig::worktrees_dir` (`<data dir>/worktrees` in the app) before saving the chat; a run starts in `Chat::work_dir()`, restoring a missing worktree first (rejected if it can't); `delete_chat` removes the worktree in the background. Tests drive `MockHarness` (`tests/engine.rs`).
- `src-tauri/` — plugins: window-state, dialog (folder picker), opener (markdown links, reveal a worktree), notification, log (debug only). Commands: `settings_*` (`src-tauri/src/settings.rs`; get/update/reset/reload/path/reveal, every change emitted as `settings://changed`); `create_chat` (optional `worktree: NewWorktree`), `list_chats`, `list_harnesses`, `update_chat_config`, `rename_chat`, `set_chat_archived`, `set_chat_pinned`, `mark_chat_seen`, `delete_chat`, `folder_icon` (`src-tauri/src/folders.rs`: a project's favicon or app icon as a data URL), `git_repo`, `git_switch_branch`, `git_create_branch`, `git_delete_branch` (`src-tauri/src/git.rs`, over `hive-git`), `provider_status`, `provider_install`, `provider_update`, `provider_sign_in` / `provider_finish_sign_in` / `provider_cancel_sign_in` (the pending CLI held in `SignIns`), `provider_sign_out` (`src-tauri/src/providers.rs`), `queue_command`, `cancel_queued`, `reorder_queue`, `send_queued_now`, `watch_messages`/`watch_chats` (stream over `Channel`s, return a watch id), `unwatch` (`src-tauri/src/engine.rs`; a webview's watchers are dropped when its page reloads). Registered harnesses: Claude Code and Mock. The main window is frameless (`decorations: false`; macOS overrides in `tauri.macos.conf.json`), so the frontend has to provide its own title bar.
- State: zustand + immer are installed.
- Path alias `@/` → `src/`.

## Conventions

- Commit messages follow Conventional Commits (`feat:`, `chore:`, `fix:`, …) with short subjects. Keep messages brief — a short subject line, body only when truly needed.
- Never add a `Co-Authored-By` trailer (or any other attribution footer) to commit messages.
- Never commit unless the user explicitly asks for it.
