# hive

Repo: https://github.com/ChillWoW/hive (private) — licensed under GPL-3.0.

## What it is

A desktop UI for driving coding-agent CLIs (Claude Code, Codex, OpenCode, …) from one place.

- No provider APIs: Hive spawns the CLIs the user already has installed (e.g. `claude` with stream-json input/output, `codex app-server`) and talks to them over stdin/stdout.
- Each CLI's output is normalized into one common event stream: text, reasoning, tool calls/results, questions, done.
- The UI renders that stream as a live transcript.

## Stack

Desktop app "Hive": Tauri 2 shell (Rust, `src-tauri/`) around a React 19 + Vite + Tailwind v4 frontend (`src/`). Package manager is bun.

## Commands

- `bun run dev` — frontend only, Vite on http://localhost:1421
- `bun run dev:local` — Tauri dev with the dev config (`Hive Dev`, blue icon)
- `bun run dev:prod` — Tauri dev with the prod config
- `bun run build` — `tsc -b && vite build` into `build/`
- `bun run lint` — oxlint
- `bun run proto` — regenerates `src/proto/` (TS types) from `crates/proto`. Also runs on any `cargo test -p hive-proto`.
- `cargo run -p hive-harness --bin hive-run -- [--mock|--codex|--opencode] [--access mode] [--plan] [--model haiku] "<prompt>"` — drive a harness from the terminal and print its events (`--json` for raw `AgentEvent`s). Answers questions and follow-ups on stdin; Ctrl+C interrupts.
- `cargo test -p hive-harness --test claude_live -- --ignored --test-threads 1` — live tests against the real `claude` CLI on Haiku (spends tokens).
- `cargo test -p hive-harness --test codex_live -- --ignored` / `cargo test -p hive-engine --test codex_live -- --ignored` — live tests against the real `codex` CLI on the account's default model (spends tokens).
- `cargo test -p hive-harness --test opencode_live -- --ignored --test-threads 1` — live tests against the real `opencode` (2.x) on its default model (spends tokens).
- `cargo run -p hive-usage --release --example report -- 30` — the Usage panel's report for this machine's last N days, printed (scan cache in a temp dir; `--data <dir>` to use another).
- `cargo test -p hive-mcp --test live -- --ignored --test-threads 1` — Claude (Haiku), Codex and OpenCode each calling a Hive MCP tool through the engine in supervised mode, and (`_waits_` tests) waiting 75s on one, past the CLIs' own timeouts (spends tokens).
- `bun run icons` — regenerates `src-tauri/icons/{prod,dev}` and `public/favicon.svg` from `src-tauri/icons/icon.svg` / `icon.dev.svg`. Use this, not `tauri icon` directly (it pads the macOS `.icns`).
- `bun run release <version>` — bumps the version (package.json, `tauri.conf.json`, `src-tauri/Cargo.toml`, Cargo.lock), commits `chore: release v<version>` and tags it; refuses a dirty tree. `git push --follow-tags` then runs `.github/workflows/release.yml` (Windows, `tauri-action`): the NSIS installer, signed for the updater (`TAURI_SIGNING_PRIVATE_KEY`/`_PASSWORD` secrets), and `latest.json` on the GitHub release. A local `tauri build` needs those env vars too (`createUpdaterArtifacts`).

## Layout

- `src/main.tsx` — entry; renders `src/App.tsx` (shell: `src/layout/` sidebar + top bar, an overlay layer below the top bar that portalled overlays mount into, the settings modal).
- `src/stores/useLayoutStore.ts` — columns: sidebar (260), conversation, right sidebar, file panel at the edge (`RightPanels`, each a `SidePanel` resized by its left edge; toggles in the top bar's right corner). Zeron's limits: files 220–440 (286 default), right ≥360 (520 default), conversation ≥300. `panelLayout`: when the minimums don't fit the window, the column opened longest ago hides (still open; toggling it brings it back as the newest). Panel open state and widths persisted as `hive.layout`. The right sidebar is `src/rightbar/`.
- `src/ui/` — Base UI–based primitives (Button, Menu, Modal, Select, …) plus `DotMatrixSpinner` (3×3 dots in random patterns for open-ended work; `pattern` holds one, e.g. `DOT_MATRIX_FULL` for waiting) and `MorphHeight` (animates its height when its content is swapped, by `swapKey`; instant otherwise) and `HiveMark` (the logo's hexagon and dot, no tile, in `currentColor`) and `FileIcon` (a file or folder's material-icon-theme icon, as VS Code resolves it: `src/lib/fileIcons.ts`, from Desktop/agent; the SVGs are separate assets, never inlined — `assetsInlineLimit` in `vite.config.ts`), exported from `ui/index.ts`. Use `FileIcon` wherever a file is shown (attachment chips, tool file badges, `@` mentions).
- `src/settings/` — settings UI and state. `store.ts`: zustand store (document, modal open/page), writes queued in order and optimistic; `useSetting(section, key)` gives a row its value, setter, `modified` and `reset`. `api.ts`: Tauri commands, localStorage fallback under plain `bun run dev`. `useSettingsRuntime` (mounted in `App`): loads, toggles the modal on the `openSettings` shortcut, re-reads the file on window focus. Add a setting only once something reads it (field in `crates/proto/src/settings.rs`, row on a page in `pages/`). Pages live in `pages/` and are registered in `pages/index.tsx`; rows use `SettingsSection`/`SettingRow`, which self-filter for search. `KeyboardPage`: a recorder per action (Escape cancels, Backspace unbinds, taking another action's combo unbinds that one), "Send with" (Enter / Mod+Enter).
- `src/keybindings/` — custom shortcut layer. Bindings live in settings (`keyboard` section, `KeyboardSettings`: strings like `Mod+Shift+P`, `Mod` = Cmd on macOS / Ctrl elsewhere, empty = unbound). `actions.ts`: the actions (id = settings key, label, `scope` global or composer, `repeats`); a new one needs a field in `KeyboardSettings` and a row here. `shortcut.ts`: parse / canonical form / from a `KeyboardEvent` (letters by `key`, punctuation by `code`) / platform display / `checkAssignable` (characters need Mod/Ctrl/Alt; editing combos reserved). `runtime.ts`: `useKeybindingsRuntime` (mounted in `App`) is the one `window` keydown listener (bubble phase, skips `defaultPrevented`; with settings open only `openSettings` runs); components handle actions with `useShortcut(id, handler)` (latest mounted wins; return false to pass the key on); `COMPOSER_SCOPE` marks the composer for composer-scoped actions. `useBinding(ref)`: an action's current binding, or a fixed combo (`Escape`) as is. Show shortcuts with `<Tooltip.Content shortcut="newChat">` (action id or fixed combo; muted text on the right, nothing while unbound) or `ShortcutKeys` (`plain` text like the sidebar Settings button, or `caps`); no native `title=` tooltips. Handlers: TopBar (new chat, new terminal, sidebar, back/forward; also the mouse side buttons), `Composer` (focus), `ChatView` (plan mode), `ChatList` (previous/next chat in sidebar order), `useSettingsRuntime` (settings), `useUsageRuntime` (usage).
- `src/chats/` — chat data layer. `api.ts`: engine commands, watches over `Channel`s (no backend under plain `bun run dev`: empty snapshots, writes reject). `store.ts`: zustand + immer store; `useChatsRuntime` (mounted in `App`) watches the chat list and sessions; `useChatMessages(chatId)` holds that chat's message watch while mounted (ref-counted `retainMessages`) and folds events with `foldEvent`. `send(target, prompt)` mints the user message id, shows the prompt from the outbox at once, creates the chat first for a `{ cwd, config }` target (and selects it), then queues a `send` command; the entry leaves the outbox when the saved message with that id arrives, or keeps the rejection as an error (`discard` drops it). `activeChatId` null is the new-chat view; `select` keeps browser-style `back`/`forward` stacks (`goBack`/`goForward`, deleted chats pruned).
  `send(target, prompt, attachments?)`: attachments ride the command and the outbox entry. Also `updateConfig` (optimistic, reverted if refused), `interrupt`, `answer`, and for queued prompts `cancelQueued`, `reorderQueued`, `sendNow` (optimistic; the outbox follows the engine's `queue` updates).
- `src/chat/ChatView.tsx` — the main pane: transcript + composer for the active chat; for the new-chat view a centred composer until the first prompt. While the live turn waits on an `input` part, `QuestionWizard` replaces the composer, the box growing into it and back (`MorphHeight`). Else a secret the agent asked for (`Session::secrets`, oldest first) shows `SecretRequestCard` there (label, reason as markdown, a masked field with show/hide, Save securely, Decline): the value goes to `answer_secret_request`, never into the chat. Queued prompts (outbox `queued`) sit in `QueuedTray` above the composer, not in the transcript: drag the handle (or arrow keys) to reorder; per row Edit (withdraws it into the draft), Send now, Remove; "paused after stop" with Resume when the queue is held. `ContextRing` sits right of the folder chip: `Chat::context` as a ring + percent (warning ≥75%, danger ≥90%, hidden until a window is reported), token counts in its tooltip — as in zeron. `UsageRing` before it (as zeron's account-usage ring): the harness's plan usage (`useProviderUsage`), the most-used window as a blue ring (warning ≥80%, danger ≥95%; hidden when the harness reports none); click opens the account (email, plan) with a meter per window and its reset time. Both draw `Ring`. `BackgroundTasks` before them: the session's `background` (agents, shells, monitors left running between turns) as a blue chip ("2 shells"); click lists each with its running time and Stop, a shell opening into the tail of its output (`chats.taskOutput`, re-read every 1.5s while open). Hidden while nothing runs. `AgentUpdates` (new-chat view, pinned to the bottom; as zeron): the enabled agents whose CLI has a newer release ("2 agent updates" pill with their marks), opening in place into a card with version → latest and Update per agent (`providers.update`); probes via `refreshProvider(id, { maxAge })` on mount and window focus, at most every 10 min; hidden while nothing is due.
- `src/sidebar/` — `ChatList` (in `layout/Sidebar`): Pinned (pin order), then each project (`useProjects` order, then folders only chats remember; first 6 chats, the open one always; "+" starts a new chat there), then Archived (folded). New-chat drafts (`useNewChatDrafts`) as `DraftRow`s at the top of their folder's project (a group added for a folder not listed; no folder yet → a Drafts section on top); click opens it, ✕ discards. `ChatRow`: a pencil in place of the time while the chat has an unsent draft; status dot (working / waiting / errored from the session, green when `isUnseen`, a dim blue dot matrix while only background tasks run), title, time ago (`time.ts`, one minute clock), harness mark; "⋯" and right-click open Rename (in place), Pin, Archive, Delete (confirm dialog). Fold state persisted as `hive.sidebar`. `useChatsRuntime` marks the open chat seen while the window has focus.
- `src/projects/` — `store.ts`: the projects picked on this device (zustand, persisted to localStorage as `hive.projects`; `add` appends one, a listed one stays put; `remove` deletes one and remembers it in `removed`, so its chats don't bring it back until it's added again). `useProjects` lists them merged with every chat's folder in a fixed order (first seen first), so projects never move. The folder picker reads it, adds each pick, and has a "⋯" menu per row (Delete).
- `src/notifications/` — `useNotificationsRuntime` (mounted in `App`), driven by the chat list watch: a session going `working` → idle/errored/closed, or to `awaitingInput`, sends a system notification (`@tauri-apps/plugin-notification`) while the window isn't focused; `awaitingInput` and a finished turn also play a chime (`playChime` in `sound.ts`: WebAudio, rising for input, falling for finished; unlocked on the first key/click). `badge.ts`: unseen non-archived chats as the dock/taskbar badge (Windows: a drawn overlay icon). Each behind a `notifications.*` setting (Notifications page).
- `src/updater/` — app updates. `useUpdaterRuntime` (mounted in `App`) checks at launch, every 4h and on window focus once an hour old (`update_check`; a failed check keeps the last result); `UpdateButton` above `SettingsButton` in the sidebar, shown while a release is out: nothing downloads until it is clicked, then unsaved editor tabs are saved (one that can't be stops it), `update_install` downloads (progress), installs and restarts. `api.ts`: a made-up update under `bun run dev` whose install fails after a fake download.
- `src/harnesses/` — harness catalogs (`list_harnesses`; a static fallback under `bun run dev`), fetched at launch and when a picker opens. `useHarnesses`: every visible one (Settings › Providers); `useCatalogs`: those turned on in the `providers` settings section (`isEnabled`, keyed by `providerKey`: `claude-code` → `claudeCode`), what pickers offer. `fitConfig` makes a `ChatConfig` valid for a catalog (keeping only `modelOptions` the model offers); `useCommands` (`commands.ts`): what the composer menus list — the live `Session::commands`, else `list_commands` for the harness and folder (on mount and window focus, fresh 30s), else the catalog's. Mock is only shown in dev builds.
- `src/providers/` — Settings › Providers data: `api.ts` (`provider_*` commands; made-up statuses under `bun run dev`; `latestRelease` reads the CLI's npm dist-tag for its channel from the webview), `store.ts` (`refreshProvider` probes a CLI and checks its newest release at most every 10 min; `usage.ts`: `refreshUsage` / `useProviderUsage` (plan usage per harness, read on mount, every 5 min, on focus, when a turn on it ends and when the card opens; at most once a minute, 30s forced; the last good reading survives a failed one); `providers.install/update/signOut` run one action at a time per harness, then `afterChange` re-probes and refreshes catalogs). The page is `src/settings/pages/ProvidersPage.tsx` (a row per harness: version, login, Install / Update / Sign in, switch; opens into account, version, location) with `SignInDialog.tsx`.
- `src/attachments/` — files sent with prompts. `api.ts`: `saveAttachment(file)` (raw bytes to `save_attachment`, 32 MB cap), `attachmentUrl` (an image read back via `attachment_bytes` as a cached object URL; `primeAttachmentUrl` hands it the composer's preview), `openAttachment` (default app). `AttachmentTile` (image thumbnail or `FileChip`; remove button, upload spinner and error in the composer, click-to-open in the transcript), `useAttachmentUrl`. As in Desktop/agent.
- `src/composer/` — `Composer` (field beside the controls while it fits one line, else a two-row box, morphing between them as in Desktop/agent; one Send/Queue/Steer/Stop button; `useSlashMenu`/`SlashMenu`: `/` at the start lists commands, `$` anywhere lists skills, as in zeron; `useMentionMenu`/`MentionMenu`: `@` starting a word lists the folder's files and folders, fuzzy-ranked (`src/lib/fuzzy.ts`), a folder completing to `@dir/` and staying open, a file to `@path `), attachments (paperclip button, paste, drop on the box; a tile row above the field; shown when the catalog has `capabilities.attachments`; Send waits until every file is copied in; a files-only prompt can be sent), `ModelPicker` (chip: harness mark (a bolt instead while fast mode is on), model, effort; card: provider tabs, search, starred models first, footer rows Fast mode (models that offer it; `hasFastMode`/`isFastMode`/`withFastMode` in `src/harnesses`) and Reasoning, each opening the picked model's choices (On/Off, levels) in a `SideCard` beside it, as in Desktop/agent), `QuestionWizard`, `AccessPicker` before the model picker (access mode + plan-mode switch, as in zeron), `FolderPicker` under the box (projects from `useProjects` with `ProjectIcon`: the folder's favicon via `folder_icon`, else a tinted monogram, as in zeron). New chats get `workspace-write`; the access mode is remembered, plan mode isn't. `store.ts`: drafts per chat, with their `DraftAttachment`s (`addFiles` copies each in, `takeAttachments` on send, `restoreAttachments` when a queued prompt is edited); several new-chat drafts (`new:<uuid>` keys): `newDraftId` is the one the new-chat view edits, `startNewChat(cwd?)` (Mod+N, a project's "+") parks it with its `newChat` settings when it has anything in it, `openDraft` swaps a parked one back, `discardDraft`, `pruneDrafts` (chats gone); drafts (text + copied files), the new chat's folder + config and starred models persisted to localStorage.
- `src/git/` — branches of a chat's folder. `store.ts`: each folder's `GitRepo` (null outside a checkout) shared by readers; `useGitRepo(cwd)` re-reads when stale (5s), on window focus and when an agent's turn in that folder ends; `useFolderBusy(cwd)` (an agent mid-turn there, by `workDir`; branch changes are disabled); `git.switchBranch/createBranch/deleteBranch` re-read afterwards. `api.ts`: `git_*` commands; an in-memory fake repo under `bun run dev`. `BranchPicker` (beside the `FolderPicker` chip, hidden outside a checkout; new-chat view only — a started chat's is `locked`, a plain label): local branches by last commit, pick to switch, type a new name to create it off the current one (Enter or the footer); per row "⋯": New branch from here (`NewBranchDialog`, creates and switches), Copy name, Delete (not the checked-out one; `DeleteBranchDialog` warns when unmerged); a branch checked out in another worktree is marked "worktree" and can't be switched to or deleted. With `onBaseChange` it picks a new worktree's base instead (nothing checked out). `WorkspacePicker` (after the branch chip, new-chat view; hidden outside a checkout): Current checkout / Worktree, kept in the composer store's `newChat.workspace` (remembered; `newChat.base` isn't). `WorkspaceChip`: a started chat's, locked; a worktree's opens its branch, base and folder with Copy path / Copy branch name / Reveal. `ChatCard` shows the branch where the chat works ("· worktree"); `DeleteChatDialog` says the worktree goes, its branch stays, and warns about uncommitted changes in it. Worktree chats keep `cwd` as their project (sidebar, folder chip); `workDir(chat)` (`src/chats`) is where the agent runs, used by the branch chip and transcript paths.
- `src/rightbar/` — the right sidebar (`RightSidebar`): the shown tab, its `TabStrip` in the top bar above it (as zeron's right pane; `TopBar` sizes that slot from `usePanelLayout`, leaving the corner to the panel toggles and window controls, over the file panel when it's wide enough; `resizing` in the layout store turns the slot's width animation off while an edge is dragged). `store.ts`: `useRightbarStore` (`tabs`: `{ kind: "file", cwd, path }`, `{ kind: "terminal", cwd }`, `{ kind: "diff" }`, `{ kind: "history" }` or `{ kind: "commit", cwd, sha, subject }`, `activeId`, `add`, `activate`, `retitle`, `remove` (the shown one passes to its right neighbour, else left), `move`), not persisted. `actions.ts`: `openFileTab(cwd, path)` (the tab it's already in, else a new one; shows the right sidebar via the layout store's `show`), `closeTab` (saves a dirty file first; a failed save keeps it open with a banner), `discardTab`. `openTerminalTab(cwd = activeFolder())` (a new terminal tab, titled with the shell once it starts; a shell exiting 0 closes its tab). `openDiffTab()` (the one diff tab, else a new one), `openHistoryTab()` (likewise), `openCommitTab(cwd, commit)` (the tab it's already in, else a new one titled with its subject). `kinds.ts`: `NEW_TABS`, what "+" offers (Terminal, with its shortcut; Diff; History). `folders.ts`: `useActiveFolder` (the open chat's `workDir`, else the new-chat folder), `openPatchFile(folder, root, path)` (a patch path, relative to the checkout root, opened in the chat's folder when it's inside it). `CommitTab` (zeron's commit-pinned Diff surface): short hash (click copies the full one) and subject, split / wrap / collapse all, then the commit's `FileSection`s (`git_commit_diff`, cached per folder and hash). `TerminalTab`: just the `TerminalView`, no toolbar. `DiffTab` (as zeron's Diff surface; follows the open chat's `workDir`, else the new-chat folder): toolbar with the scope menu (Working tree / Branch changes / Latest turn; titles the tab), for branch changes `{branch} → {base ⌄}` (saved per checkout root, else main/master, else the newest other branch), split, wrap, collapse all; a summary strip (count, +N −N, "Partial snapshot"), then a `FileSection` per file; a file opens in a file tab (path mapped from the root to the chat's folder). `ToolButton`: the tab toolbars' icon button. `TabStrip`: zeron's chips (112×24, 4px gap; file icon, title, ✕ on hover over the unsaved dot; the path in a tooltip, instant from tab to tab via `Tooltip.Provider`), scrolls sideways (wheel too) with faded edges, drag to reorder (others slide a slot aside), middle-click closes; the shown tab is scrolled into view. `FileTab`: zeron's toolbar (icon, `›` path, status label: Save failed (click retries) / Save conflict / Changed on disk / Deleted on disk; Markdown preview/code, show in file tree, open in default app, wrap), banners (close blocked, changed or conflict: Reload from disk / Overwrite, deleted, read-only reason), then the `CodeEditor`, a Markdown preview (the default for `.md`), an image preview, or why it can't be shown. `useDiskChecks`: open files are looked at again on window focus and when an agent's turn ends in their folder (no watcher yet).
- `src/diff/` — the diff tab's data and rows (zeron's `crates/ui/src/changes.rs`). `patch.ts`: `parsePatch` (unified git patch → `FileDiff`s: hunks, lines with old/new numbers, status, binary, +/− counts), `parsePatchReusing` (keeps unchanged files' objects across refreshes), `splitPairs` (a hunk's split rows). Every file starts folded in the diff and commit tabs. `highlight.ts`: `highlightFile` — the old and new sides each parsed as one document by the editor's lezer language (`@codemirror/language-data`), coloured with the editor's `HIGHLIGHT_SPECS` as inline styles; cached, skipped past 5000 lines. `store.ts`: `useDiffPrefs` (scope, split, wrap, base per root; `hive.diff`), `useCheckoutDiff(cwd, base, enabled)` (`git_diff` on mount, focus, a turn starting/ending there, every 5s (2s while an agent works there) while the window has focus; an unchanged patch keeps the old entry), `useTurnDiff(cwd, chatId, enabled)` (`git_turn_diff`, the open chat's latest turn: never polled, read on mount, focus, the chat starting/ending a turn and whenever the working-tree patch changes; null → "No turn recorded yet"). `DiffFiles.tsx`: `FileSection` (sticky header: chevron, icon, path, +N −N, open; `content-visibility: auto`), unified rows (two number gutters, marker, code; gutters sticky while code scrolls sideways) or split (two columns scrolling sideways on their own, or paired rows when wrapping), on zeron's emerald / red washes with a 3px accent bar.
- `src/history/` — the history tab (zeron's `crates/ui/src/history.rs`). `graph.ts`: `layoutGraph` (commits children first → per row the node's lane and colour id plus its segments: lanes passing through, ending in the node, leaving it; colour id = path identity), `compactToVisible` (a subset with parents carried across the left-out commits; mirrors the Rust one), `historyMatches` (hash prefix, or each word a subsequence of "hash subject"; mirrors the Rust one), `collapseBranchRuns` (a folded branch's lane loses its plain commits; refs, merges, branch points stay), `graphGeometry` (natural 12px lanes, squeezed to ≤34% of the tab and the subject's 80px, else a one-lane rail, with hysteresis), ref-badge fitting. `api.ts`: `git_history` / `git_search_history` / `git_fetch_all` / `git_commit_diff` / `git_avatars`, pages of 100; a made-up ~250-commit repository under `bun run dev`. `store.ts`: `useHistoryStore` (per folder: loaded pages, branch tips, HEAD, counts, comparison, search, fetch state, avatars), `loadHistory(cwd, reset?)` (first page; without `reset` the loaded older pages stay when the top is unchanged), `loadOlder`, `setSearchQuery` (loaded rows filter at once, the whole history's matches after 70ms), `fetchAll` (then the history from the top and the branch picker re-read), avatars asked per page; `useHistoryPrefs` (columns Author/Date/SHA, author as picture or name; `hive.history`). `HistoryTab` (follows the open chat's folder): toolbar (branch, "N commits", ahead/behind vs the integration branch when wide enough, search field, Fetch all, branch-tips view, Refresh), a header with the columns menu (on hover), rows drawn only near the viewport (36px): a per-row SVG graph cell (HEAD ringed; hovering a path or row brings its colour forward and dims the rest; a branch tip's fold button on hover), subject, ref badges (branch / remote / tag, "+N"), author, date, hash (click copies); Load more at the end. A row opens its commit (`openCommitTab`). Read when shown, when HEAD or the branch moves, when an agent's turn there starts or ends, and on window focus. Not yet: zeron's column resizing and reordering, fold/compact animations.
- `src/terminal/` — terminals (xterm.js 6: fit, web-links (opener), WebGL with DOM fallback). `sessions.ts`: one xterm + shell per tab id, kept outside React (`createSession`; `attachSession` moves its element into the view, opens it and starts the shell on first show, refits on resize; `disposeSession` kills the shell; a non-zero exit is printed in it). Keys: an app shortcut (`isAppShortcut`) passes through to the app; off macOS Ctrl+C copies a selection (Ctrl+Shift+C always), Ctrl+V / Ctrl+Shift+V paste. `theme.ts`: `dark-850`, the editor's font, GitHub Dark ANSI colours. `api.ts`: `terminal_*` commands (rejects under `bun run dev`).
- `src/editor/` — the file editor (CodeMirror 6). `documents.ts`: an open file per tab id (`useDocsStore`: phase, last `FileText`, `dirty`, `saving`, `status`, `closeBlocked`, Markdown `preview`, `version`); each one's `EditorState` lives outside React (kept while its tab is off screen, so undo and selection survive), its language loaded lazily by file name (`@codemirror/language-data`). Dirty = the text differs from what was last read or saved. `save` (Mod+S in the editor) writes with the hash it was read with; `checkDisk`: same hash, nothing; clean, takes the new text quietly (not undoable); dirty, `changed`. `reloadFromDisk`, `overwrite`. Read-only files open uneditable. `useEditorPrefs`: `wrap`, persisted as `hive.editor`. `theme.ts`: app surfaces, `github-dark-default` syntax colours. `api.ts`: `read_file`/`write_file`/`read_file_bytes`/`open_file` (an in-memory fake under `bun run dev`).

## Conventions

- Commit messages follow Conventional Commits (`feat:`, `chore:`, `fix:`, …) with short subjects. Keep messages brief — a short subject line, body only when truly needed.
- Never add a `Co-Authored-By` trailer (or any other attribution footer) to commit messages.
- Never commit unless the user explicitly asks for it.
